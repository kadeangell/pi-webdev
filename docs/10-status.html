Current state

The canonical "what works right now" reference. The eight-week MVP from the roadmap is complete: six subsystems, 34 WDP methods, 37 end-to-end assertions, all running against real Lightpanda, real tsserver, real Vitest, and real ESLint.

This is built software, not a plan. Every method below is registered and dispatchable; every subsystem below boots. The numbers come from pnpm smoke on the merged main branch. What's not here is equally honest — see §10.6.

10.5Install & run

# Build from source (Node 22+, pnpm 10+)
pnpm install && pnpm -r run build

# Optional: install Lightpanda for the browser subsystem
#   https://lightpanda.io — drop the binary in PATH or set LIGHTPANDA_BIN

# Set up a project
pi-webdev init                  # detect stack, write pi-webdev.config.json
pi-webdev daemon install        # systemd (Linux) / launchd (macOS) unit
pi-webdev serve                 # …or run in the foreground

# Drive it
pi-webdev --auto caps                          # one-shot, ephemeral server
pi-webdev --auto browser eval URL "document.title"
pnpm smoke                                     # 37-assertion end-to-end run

10.6Honest gaps

What an 0.1 explicitly does not do yet:

  • The Pi extension binds a stub host. It implements the documented defineExtension shape but doesn't yet import Pi's real package — that waits on pinning a Pi version and reading its source (roadmap §7.8 step 1).
  • One browser target per process. Lightpanda rejects a second Target.createTarget with TargetAlreadyLoaded; sessions are effectively serial for now.
  • No layout in the browser. Lightpanda gives DOM + JS but no rendered geometry — browser.dom text isn't whitespace-accurate, and there are no click coordinates or screenshots.
  • Hook values are indexed, not named. inspect.state returns hooks[0]=7, not count=7; source-map-aware naming is 0.2.
  • Single tsserver, inferred-project mode. Per-tsconfig isolation isn't implemented.
  • Restart-with-backoff is off. The registry tracks crashes but doesn't auto-restart yet — no real crash data to tune against.
  • Not published to npm. Packages are publish-ready; the actual pnpm publish is a deliberate, credentialed step left to the maintainer.

The future roadmap sequences these against new capability.
